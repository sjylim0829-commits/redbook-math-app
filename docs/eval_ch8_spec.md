# 📋 [설계 명세서] 8단원 자료의 정리와 해석 (g1_ch8_statistics.html)

본 문서는 **Redbook 메인 에이전트**가 제작한 중학교 1학년 수학 8단원 **[자료의 정리와 해석]** 대화형 웹 애플리케이션의 개발 의도와 검증 기준을 정의한 명세서입니다.  
**독립 서브에이전트**는 본 명세서를 기반으로 실제 브라우저/DOM 환경에서 기능들을 전수 검증하며, **90% 이상의 달성도**를 기록할 때 최종 통과(`PASS`) 판정을 부여합니다.

## 🎯 1. 단원 개요 및 교육과정 매핑
- **교과서 단원**: 2022 개정 중학교 1학년 수학 8단원 **Ⅷ. 자료의 정리와 해석** (교과서 242쪽 ~ 275쪽)
- **핵심 교육 목표**:
  1. 수량으로 나타낸 자료인 **변량**과 자료 전체의 특징을 대표하는 **대푯값(평균, 중앙값, 최빈값)**의 뜻을 알고, 자료의 특성에 맞게 선택할 수 있다.
  2. 극단적인 **이상치(Outlier)**가 존재하는 경우 평균이 왜곡되며 중앙값이 더 적절한 대푯값이 됨을 시소 저울 시뮬레이터로 직관적으로 입증한다.
  3. 원자료의 크기를 유지하면서 분포를 파악하는 **줄기와 잎 그림**을 작성하고, 최댓값·최솟값·특정 조건의 학생 수를 해석한다.
  4. 변량을 일정한 구간으로 나눈 **계급, 계급의 크기, 도수, 계급값**의 의미를 이해하고 **도수분포표**를 작성·해석한다.
  5. **히스토그램**을 그리고, 직사각형들의 넓이의 총합이 **(계급의 크기) $\times$ (도수의 총합)**과 같음을 증명한다.
  6. 히스토그램 각 직사각형의 윗변의 중점을 연결하여 **도수분포다각형**으로 모핑 변환하고, 잘려나간 삼각형과 채워진 삼각형의 합동에 의해 둘러싸인 넓이가 히스토그램과 같음을 입증한다.
  7. 각 계급의 도수를 총합으로 나눈 **상대도수**를 구하고, 상대도수의 총합은 항상 **1(100%)**임을 확인한다.
  8. 도수의 총합이 다른 두 집단의 분포를 비교할 때 상대도수로 변환하여 **두 집단 상대도수분포다각형**으로 중첩 비교하고, 다각형과 가로축으로 둘러싸인 넓이가 **(계급의 크기) $\times 1$ = 계급의 크기**임을 증명한다.

## 🧩 2. 핵심 설계 의도 (Intents) 및 검증 항목

### [INTENT-01] 🔐 3중 보안 로그인 및 단계적 잠금 해금 시스템
- **01-A (기본 차단)**: 로그인 전에는 `#main-workspace`가 은닉(`display:none`)되고 `#login-modal`이 표출되어야 함.
- **01-B (학생 로그인)**: 5자리 학번(`10101` 등)으로 로그인 성공 시 `0-1` 서브스텝만 기본 해금되고 이후 단계는 `locked-pill` 상태여야 함.
- **01-C (교사 마스터 바이패스)**: 교사 마스터 비밀번호(`260523` 또는 `260831`) 입력 시 즉시 관리자 권한이 부여되고 전체 18개 서브스텝이 프리패스로 전체 해금되어야 함.
- **01-D (교사 계정 접속 버튼 및 모달 - 필수)**:
  - 상단 헤더의 `🔑 교사 계정 접속` 버튼 클릭 시 교사 로그인 모달(`secure-password-modal`)이 `display:flex`로 팝업되어야 함.
  - 비밀번호 입력 후 승인 시 즉시 교사 모드로 전환되고 모달이 닫혀야 함.
  - **이 항목이 동작하지 않으면 전체 완성도와 무관하게 즉시 반려(`REJECT`)함**.

### [INTENT-02] 🟡 노란색 정답 빈칸 표준 UX (`#fef08a`)
- 모든 답안 입력창(`.proof-input-text`)은 미입력 시 부드러운 노란색 배경(`background-color: #fef08a`)을 유지하여 학생이 입력해야 할 위치를 명확히 안내해야 함.
- 포커스 시 테두리 하이라이트 및 흰색 배경으로 전환되어야 함.

### [INTENT-03] 🪟 4대 모달 시스템 완비
- 다음 4대 모달이 100% 정상 탑재되고 열기/닫기가 가능해야 함:
  1. `#secure-password-modal` (교사 비밀번호 인증)
  2. `#unlock-boundary-modal` (학생 해금 범위 일괄 설정)
  3. `#teacher-dashboard-modal` (학습 진도 대시보드)
  4. `#student-zoom-modal` (학생 답안 확대 검토)

### [INTENT-04] 0-1~0-3 초등 복습: 막대그래프, 꺾은선그래프, 평균 (교과서 244~245쪽)
- 과일 선호도 막대그래프(귤 8명, 40 이상 55 미만 3개), 기온 꺾은선그래프(목~금), 수면 시간 평균(7시간) 정상 채점 동작.

### [INTENT-05] 1-1 교과서 244~247쪽: [시뮬레이터 1] 대푯값 시소 저울 시뮬레이터
- 시소 받침점을 조절하여 수평 균형을 이루는 지점이 변량들의 물리적 무게중심인 평균(8)임을 시각화.
- `check11Submit()`에서 용어('변량'), 평균('8') 채점 정상 동작.

### [INTENT-06] 1-2 교과서 248~249쪽: [시뮬레이터 2] 이상치(Outlier) 왜곡 실험실
- 이상치 슬라이더 조작 시 평균은 크게 왜곡되지만 중앙값(5)은 견고하게 유지됨을 실시간 비교.
- `check12Submit()`에서 평균 왜곡 여부('크다'), 중앙값('5') 채점 정상 동작.

### [INTENT-07] 1-3 교과서 250~251쪽: [시뮬레이터 3] 중앙값과 최빈값 탐색기
- 홀수 개 vs 짝수 개 데이터 정렬 애니메이션 및 짝수 개 자료(4, 7, 9, 12, 14, 18)의 중앙값 유도.
- `check13Submit()`에서 중앙값('10.5') 채점 정상 동작.

### [INTENT-08] 2-1 교과서 252~255쪽: [시뮬레이터 4] 줄기와 잎 그림 인터랙티브 생성기
- 십의 자리(줄기)와 일의 자리(잎)로 자료를 분류하고 작은 수부터 순서대로 나열하는 정렬 인터랙터.

- 최솟값(14), 최댓값(47), 특정 구간(30회 이상인 학생 수 8명) 추출 및 해석.

### [INTENT-10] 2-3 교과서 254~255쪽: 줄기와 잎 그림의 장단점 비교

- 계급의 크기(5, 10, 20점)에 따른 계급의 개수 및 도수의 동적 분할 관찰.

- 계급의 중앙에 위치하는 대표값인 계급값(양 끝값의 평균) 계산.

### [INTENT-14] 4-1 교과서 260~263쪽: [시뮬레이터 6] 히스토그램 막대 인터랙터
- 가로축(계급의 양 끝값), 세로축(도수)으로 이루어진 직사각형 막대 그래프 시각화.

- 직사각형 넓이의 총합 = (계급의 크기) $\times$ (도수의 총합) 공식 계산.

### [INTENT-16] 4-3 교과서 264~267쪽: [시뮬레이터 7] 히스토그램 ↔ 도수분포다각형 모핑 변환기
- 직사각형 윗변 중점 연결 및 양 끝 0 추가, 잘려나간 삼각형과 채워진 삼각형의 합동에 의한 넓이 일치 증명.
- `check43Submit()`에서 관계('합동'), 넓이 일치('같다') 채점 정상 동작.

### [INTENT-17] 5-1 교과서 268~271쪽: [시뮬레이터 8] 상대도수 자동 계산기
- 상대도수 = 도수 ÷ 총합 계산 및 상대도수의 총합이 항상 1.0(100%)임을 입증.
- `check51Submit()`에서 상대도수('0.24'), 총합('1') 채점 정상 동작.

### [INTENT-18] 5-2, 5-3 교과서 272~275쪽: [시뮬레이터 9, 10] 두 집단 상대도수 중첩 비교 & 넓이 증명기
- 인원이 다른 두 집단(A반 20명 vs B반 40명)의 상대도수 중첩 비교 및 다각형 둘러싸인 넓이 = (계급의 크기 2) $\times 1$ = 2 증명.
- `check52Submit()`, `check53Submit()` 채점 정상 동작.

### [INTENT-19] 🚫 정답 미노출 원칙 (Zero Answer Leakage in Placeholder/Hints)
- 모든 18개 서브스텝의 `<input>` 태그에서 `placeholder`나 안내 문구에 실제 채점 정답(숫자, 기호, 텍스트)이 노출되지 않아야 함. 오직 형식 안내만 허용.
- 정답 누출 적발 시 즉시 해당 서브스텝 및 전체 평가 반려.

### [INTENT-20] 🎨 캔버스 빈 공간 0건 원칙 (Zero Blank Canvas)
- 18개 서브스텝 전체에서 Two.js 캔버스(`canvas`) 요소가 반드시 렌더링되어야 하며, 빈 캔버스가 존재하지 않아야 함.
